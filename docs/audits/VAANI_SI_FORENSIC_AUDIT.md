### 2.2 Production Backend Bifurcation Risk

There are **two competing backend applications** in the repository:
1. `apps/server` (`@dhwani-si/server`, port 4000): Hosts the WebSockets, Exotel telephony webhooks, and domain APIs. Registered in root `package.json` as `npm start`.
2. `apps/api` (`@vanni/api`, port 4100): Hosts a duplicate set of REST routes (`auth`, `crm`, `agents`, `billing`).
3. **Deployment Discrepancy:** `docker-compose.yml` specifies `api-server` building `./apps/server` but exposes port `4100` with variable `API_PORT: 4100`, whereas `apps/server` defaults to `PORT 4000`. Furthermore, `docker-compose.yml` attempts to run `npm run dev` inside `apps/web` expecting Next.js, while `apps/web` is a static HTML generator.

## 5. Authentication & Authorization Trace

### 5.1 Architecture & Tokens
- **Mechanism:** HMAC-SHA256 signed session tokens generated by `serializeSession()` in `packages/auth`.
- **Cookie Security:** `httpOnly: true`, `sameSite: 'lax'`, `path: '/'`. Secure flag conditioned on production.
- **Header Alternative:** Supports `Authorization: Bearer <token>`.

### 5.2 Confirmed Defects & Redirect Flaws
1. **Demo Session Schema Mismatch (Root Cause of Infinite Login Loop):**
   - In `apps/web/login.html`, `loginAsDemo()` sets `localStorage.setItem('vanni_session', JSON.stringify(sess))` where `sess` contains `{ userId, email, activeOrganizationId, memberships }`.
   - In `apps/web/app/agents.html` (line 604) and `apps/web/app/knowledge.html` (line 480), the authentication guard executes:
     ```javascript
     if (parsed && (parsed.authenticated || parsed.user)) { session = parsed; }
     if (!session) { window.location.href = '/login'; }
     ```
   - Because `sess` lacked the property `user` or `authenticated`, the check evaluates to falsy, and the user is immediately redirected to `login.html` when clicking "AI Employees" or "Knowledge Brain".
2. **Missing Dev Account Pre-seeding in Local / File-backed Database:**
   - `IdentityService` in `packages/auth/src/identity-service.ts` deliberately removed seeded users to satisfy an earlier security audit.
   - When a developer or tester runs locally without Supabase credentials, `auth_store.json` is empty. `POST /api/auth/login` fails with 401 Unauthorized for all demo accounts (`agency.demo@vanni.ai`, `realestate.demo@vanni.ai`, `healthcare.demo@vanni.ai`).

## 8. Dead Code & Duplicate Implementations

1. **`apps/api` vs `apps/server` Duplication:**
   - `apps/api/src/routes/billing.ts` duplicates `apps/server/src/routes/billing.ts`.
   - `apps/api/src/routes/analytics.ts` duplicates `apps/server/src/routes/analytics.ts`.
   - `apps/api/src/routes/auth.ts` duplicates inline auth routes in `apps/server/src/server.ts`.
   - **Recommendation:** Harmonize into `apps/server` as the authoritative backend.
2. **Obsolete Build Script:**
   - `apps/web/build-auth-pages.mjs` is completely unreferenced in `package.json`; its logic was absorbed by `apps/web/build-all-pages.mjs`.
3. **Docker Compose Desynchronization:**
   - `docker-compose.yml` specifies `command: sh -c "npm install && npm run dev"` inside `apps/web` assuming Next.js exists. This will terminate immediately upon generating static HTML files.
